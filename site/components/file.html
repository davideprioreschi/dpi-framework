file

Scelta file con elenco, rimozione e trascinamento, sopra l'input nativo.

  • Esempi
  • Contratto
  • Comportamento
  • Parti incomplete

Esempi

Singolo

<div class="dpi-field">
  <label class="dpi-label" for="f-1">Documento</label>
  <div class="dpi-file" data-dpi-file><input class="dpi-file__input" id="f-1" type="file" name="documento" accept=".pdf,image/*"></div>
</div>

Multiplo con rimozione del singolo file

<div class="dpi-field">
  <label class="dpi-label" for="f-2">Allegati</label>
  <div class="dpi-file" data-dpi-file><input class="dpi-file__input" id="f-2" type="file" name="allegati" multiple></div>
</div>

Area di trascinamento, in un form con reset

<form class="dpi-stack" onsubmit="return false">
  <div class="dpi-field">
    <label class="dpi-label" for="f-3">Immagini</label>
    <div class="dpi-file" data-dpi-file data-dpi-file-drop><input class="dpi-file__input" id="f-3" type="file" name="immagini" accept="image/*" multiple required></div>
  </div>
  <div class="dpi-cluster"><button class="dpi-btn dpi-btn--primary" type="submit">Invia</button><button class="dpi-btn" type="reset">Azzera</button></div>
</form>

Cartella

<div class="dpi-field">
  <label class="dpi-label" for="f-4">Cartella</label>
  <div class="dpi-file" data-dpi-file data-dpi-file-dir><input class="dpi-file__input" id="f-4" type="file" name="cartella"></div>
</div>

Contratto del markup

Basta il contenitore con data-dpi-file e l'<input type="file"> nativo: il resto lo crea DPI.init (anche su frammenti inseriti dopo, senza duplicare). Si può scrivere a mano; le parti presenti vengono riusate. Struttura risultante:

<div class="dpi-file" data-dpi-file [data-dpi-file-drop] [data-dpi-file-dir]>
  <input class="dpi-file__input" type="file" name="…" accept="…" multiple required>   <!-- nativo, nascosto in modo accessibile -->
  <div class="dpi-file__bar">
    <button class="dpi-btn dpi-file__pick" type="button">Scegli file…</button>
    <span class="dpi-file__hint">Nessun file selezionato</span>
    <button class="dpi-btn dpi-btn--plain dpi-btn--sm dpi-file__clear" type="button" hidden>Rimuovi tutti</button>
  </div>
  <ul class="dpi-file__list" role="list" aria-live="polite"> <li class="dpi-file__item">nome · dimensione · Rimuovi</li> </ul>
  <p class="dpi-file__error dpi-error" role="alert" hidden></p>
</div>
Contratto
NomeCosa fa
data-dpi-fileContenitore; abilita il componente.
data-dpi-file-dropIl contenitore diventa area di trascinamento (rispetta accept e multiple; con multiple aggiunge ai file esistenti). Non attivo con -dir.
data-dpi-file-dirSelezione di cartelle (webkitdirectory): l'elenco mostra una sola riga riepilogativa.
data-dpi-file-label / -hint / -emptyTesti: pulsante, suggerimento nella dropzone, stato vuoto.
DPI.file.sync(el)Ridisegna l'elenco dopo modifiche da codice a input.files o a un fieldset disabilitato.
dpi:file-rejectedEvento (detail.files) per i file scartati nel trascinamento perché non ammessi da accept.

Comportamento

  • L'input nativo conserva name, accept, multiple, required, disabled, form, FormData e change; form.reset() ripulisce anche l'elenco.
  • Rimuovere un file aggiorna input.files con DataTransfer e rilancia input e change; con file singolo il pulsante è «Rimuovi», con più file è una X per riga più «Rimuovi tutti».
  • Il pulsante è un dpi-btn raggiungibile da tastiera con focus visibile; il nome accessibile unisce l'etichetta del campo e il testo; l'elenco è una regione aria-live="polite".
  • Il nativo non è display:none (così required può segnalare l'errore): è ridotto a 1px e fuori dal tab; su invalid il focus passa al pulsante.

Parti incomplete

Il trascinamento di cartelle non è supportato (il browser non le espone come file). Non verificato in un browser dall'agente; Firefox e WebKit mai provati.
